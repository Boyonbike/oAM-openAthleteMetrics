     Plan: Auto-sync daily weight to UserProfile on DailyContext upsert

     Context

     When a user logs their weight as part of a daily context entry, the user
     profile should stay in sync automatically. Currently
     RoomDailyContextRepository.upsert only writes to daily_context; the
     user_profile table is never touched. This change wires the two repositories
     together so a non-null weightKg on any DailyContext upsert is reflected in
     the profile without any caller change.

     ---
     Files to change

     1. app/src/main/java/com/athletedata/openAthleteMetrics/data/repository/Roo
     mDailyContextRepository.kt

     Constructor — add UserProfileRepository as a second injected parameter:

     @Singleton
     class RoomDailyContextRepository @Inject constructor(
         private val dao: DailyContextDao,
         private val userProfileRepository: UserProfileRepository,
     ) : DailyContextRepository

     upsert method — after the Room write succeeds, conditionally call
     updateWeight:

     override suspend fun upsert(context: DailyContext) {
         try {
             dao.upsert(context.toEntity())
         } catch (e: Exception) {
             Timber.e(e, "Failed to upsert daily context")
             throw e
         }
         // Only sync when weight was explicitly provided; null means "not 
     entered",
         // not "clear the profile weight".
         context.weightKg?.let { kg ->
             try {
                 userProfileRepository.updateWeight(kg)
             } catch (e: Exception) {
                 Timber.e(e, "Failed to sync weight to user profile")
                 // Swallow — a profile-sync failure must not roll back the 
     daily context save.
             }
         }
     }

     Key points:
     - The dao.upsert try-catch is preserved and still re-throws; the
     daily-context write can still fail fast.
     - The updateWeight call is in its own try-catch that swallows, per
     requirements.
     - context.weightKg?.let ensures null safety — no updateWeight call when
     weight is absent.

     2. 
     app/src/main/java/com/athletedata/openAthleteMetrics/di/DatabaseModule.kt

     No changes required. Both DailyContextRepository → 
     RoomDailyContextRepository and UserProfileRepository → 
     RoomUserProfileRepository are already bound as @Singleton in
     DatabaseModule. Hilt resolves the UserProfileRepository interface and
     injects it into RoomDailyContextRepository automatically.

     ---
     Dispatcher note

     upsert is already a suspend fun called on Dispatchers.IO by Room
     conventions (callers use viewModelScope or an IO dispatcher). No additional
     withContext wrapping is needed; updateWeight in RoomUserProfileRepository
     also runs the DAO call as a suspend function under the caller's dispatcher.

     ---
     Verification

     1. Build: ./gradlew assembleDebug — confirms Hilt wiring compiles with no
     circular-dependency errors.
     2. Run the app, open Daily Context screen, enter a weight, save.
     3. Navigate to Profile screen — confirm the weight field matches what was
     entered.
     4. Save a Daily Context with no weight — confirm the existing profile
     weight is unchanged.
     5. Simulate updateWeight throwing (temporarily add throw 
     RuntimeException("test") in RoomUserProfileRepository.updateWeight) —
     confirm the daily context save still succeeds and the error is logged but
     not surfaced.
