     Plan: Wire SyncContext into BleEngine Connect Flow

     Context

     Drivers can optionally declare a syncRequirements block in their manifest
     to signal that they need datetime and/or user-profile data before building
     sync commands. Currently BleEngine.beginSyncCommandExecution() calls
     driverRegistry.buildEffectiveSyncCommands() which executes a no-arg WASM
     export (unexercised, has a TODO) and prepends results to
     manifest.syncCommands. The task replaces that flow with a context-aware one
     where:

     - SyncContextFactory is injected into BleEngine
     - The manifest is read for syncRequirements to decide whether to hit the DB
     - A context-aware WASM buildSyncCommands(offset, len) call produces
     commands that are appended to the static list
     - Factory errors are caught; static commands execute unaffected

     2. WasmDriverEngine.kt

     Add a new public suspend method buildSyncCommands(manifest, context). This
     replaces the intent of the current private callBuildSyncCommands() (which
     uses a no-arg WASM call that has never been exercised against a real device
     per its own TODO). The new method:

     - Uses the same WasmExports.buildSyncCommands export name
     - Serializes SyncContext to JSON via the already-injected
     SyncContextSerializer
     - Writes JSON bytes to WASM memory at IN_OFFSET_V2 (offset 16), just like
     callParse writes BLE bytes
     - Calls the WASM export with (IN_OFFSET_V2, jsonBytes.size) params —
     matching the (param i32 i32) parse-function convention
     - Reads commands from CMD_OUT_OFFSET (0x400) and deserializes as
     List<SyncCommand.Write>
     - Returns emptyList() gracefully if export absent, output is zero-length,
     or any exception
