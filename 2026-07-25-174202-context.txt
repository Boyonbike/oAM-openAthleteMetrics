  Engine + background
  - cleanup: MultiDeviceSyncOrchestrator.syncOneDevice/finishDevice have no
  try/catch around the connect/observe/cleanup sequence — failure isolation
  instead relies on every failure path resolving to a BleConnectionState value
  (Error, Disconnected) or a bounded withTimeoutOrNull. This works in the traced
  code paths but means a genuinely-thrown exception from
  bleEngine.connectToDevice() (e.g. an unexpected SecurityException not caught
  inside BleEngine) would propagate up through runSequentialSync()'s
  forEachIndexed and abort the entire run rather than skip just that device —
  contradicts the "isolates failures" goal for that specific failure mode.
  BleEngine.connectToDevice (BleEngine.kt:228-243) does catch SecurityException
  internally and turns it into an Error state, so this specific case is covered,
  but there's no blanket boundary if a new call site inside syncOneDevice
  throws something else in the future.
