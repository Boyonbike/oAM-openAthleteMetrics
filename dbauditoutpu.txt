  FAILED-11
  File: worker/DailySummaryWorker.kt:66–88 · Severity: Medium

  The resting HR window and morning HRV window are both anchored to UTC, not the
  user's local timezone:

  val nightEndMs     = date.atTime(6,
  0).toInstant(ZoneOffset.UTC).toEpochMilli()   // midnight–06:00 UTC
  val morningStartMs = date.atTime(5,
  0).toInstant(ZoneOffset.UTC).toEpochMilli()   // from 05:00 UTC

  For a user in UTC+10, "midnight UTC" is 10:00 AM local time. The resting HR
  window (00:00–06:00 UTC) would capture afternoon readings, not overnight
  resting readings. The "morning HRV" (from 05:00 UTC) would capture the midday
  HRV, not the post-wake reading.

  Recommended fix: Use the device's local timezone (or a persisted user
  timezone) for these time boundary calculations. ZoneId.systemDefault() would
  be appropriate for a local-only Android app, or store a userTimezone in
  DataStore and retrieve it before computing boundaries.

  FAILED-12
  File: seeder/SeederService.kt:107–220 · Severity: Medium

  seedDays() has no try/catch around individual repository calls. A failure
  partway through (e.g., a Room SQLiteConstraintException on
  sleepRepository.insert()) will propagate to SeederViewModel, which catches it
  and displays SeederState.Error. However, the database will be left in a

  dates were affected.

  Recommended fix: Wrap the entire seedDays() call in a database transaction
  where possible, or at minimum add per-day try/catch and log/skip failures
  individually so that one bad date doesn't abort the entire run.
